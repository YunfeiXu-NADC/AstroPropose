# DSL RPS 双提案流程设计

## 共用规则

- 提案类型必须显式选择为“DSL 研究提案”或“DSL 机遇观测提案”。
- 目标可见性计算是填写观测目标时调用的提交前工具，不是提交后的审批节点。报告随提案一起提交。
- 管理员可查看全部提案、类别和进度；普通提案者只能查看本人提案。
- 系统只做格式校验、几何计算和流程流转，不自动判断科学价值，也不强制规定评分标准。

## DSL 研究提案流程

`草稿 → 形式审查 → 技术评审 → 科学评审 → 科学委员会决策 → 观测编排 → 观测执行 → 数据匹配 → 数据授权 → 完成`

- 草稿：填写基本信息、科学目标、仪器（高频/低频）、目标坐标、观测时间范围和附件；可按需运行可见性分析。
- 形式审查：提案管理员检查完整性与格式，可退回修改。
- 技术评审：技术专家评估仪器、几何条件和可执行性，可退回修改。
- 科学评审：提案管理员分配多位科学专家；专家保存草稿或提交评分与评语。
- 委员会决策：汇总技术与科学意见，形成批准、驳回或修改决定。
- 观测与数据：批准后进入观测编排；数据生成后自动匹配提案，并授予提案者访问权限。
- 异常：元数据自动匹配失败时进入“手动数据关联”，由管理员绑定后再授权。

## DSL 机遇观测提案流程

`草稿 → 形式审查 → 技术评审 → 快速科学评审 → 快速决策 → 推送观测编排 → 执行反馈 → 完成`

- 申请内容突出目标时效、触发条件、响应窗口和仪器需求；同样可在提交前运行可见性分析。
- 评审链条与研究提案相同，但在界面和催办策略上标记为快速流程。
- 批准后将提案与全部评审意见推送给观测编排负责人。
- 提案者可查看评审与执行反馈；本流程不自动进行研究数据分配。

## 角色与权限

| 环节 | 允许角色 |
| --- | --- |
| 创建、修改、提交 | Proposer |
| 形式审查、分配专家、流程管理 | Admin / 提案管理员 |
| 技术评审 | Technical Expert |
| 科学评审 | Reviewer |
| 最终决策 | Panel Chair / 科学委员会 |
| 观测编排与执行反馈 | Instrument Scheduler |
| 数据关联与授权 | Admin |

## 超时与异常

- 专家逾期：系统自动催办并抄送提案管理员，管理员可重新指派。
- 可见性服务失败：保留输入和请求记录，允许重试，不自动改变提案审批状态。
- 数据匹配失败：进入人工关联队列，不影响已经形成的审批结果。

系统中的可执行预设位于 `frontend/lib/dslWorkflowPresets.mjs`，管理员可在“系统配置 → 流程管理”中一键安装或更新两套流程。
